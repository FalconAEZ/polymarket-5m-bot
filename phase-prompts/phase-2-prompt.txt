TASK 2.0 — Design the data plane (DESIGN DOC ONLY, NO CODE)
--------------------------------------------------------------------------------

Write `design/data_plane.md`. Lock the following decisions before any code:

1. **Async architecture.** Three feeds run as separate `asyncio.Task`s. A
   shared async queue feeds a single Parquet writer task. No threads. Single
   event loop.

2. **Storage schema (PINNED — must not drift).** Per-source Parquet files,
   schema:
     `ts_utc_ns: int64` (event time, nanoseconds since epoch UTC)
     `received_at_ns: int64` (local clock when our process saw it)
     `source: str` ("binance", "coinbase", "oracle", "polymarket")
     `kind: str` (free-form per source: "trade", "book_top", "AnswerUpdated", "book", "trade")
     `payload_json: str` (raw upstream payload, no transformation)

   Two timestamps deliberately. `ts_utc_ns` is what the upstream said;
   `received_at_ns` is our own clock. Skew between them is itself a
   metric we'll mine in Phase 3.

3. **Storage layout.** `ticks/<UTC-date>/<source>.parquet`. Rotate at UTC
   midnight. New file per day per source. The directory `ticks/` is
   gitignored (large + non-deterministic).

4. **Reconnect policy.** Exponential backoff starting at 1s, capping at
   60s. Reconnect attempt cycle: 1s, 2s, 4s, 8s, 16s, 32s, 60s, 60s, 60s…
   If a feed is down for > 5 min cumulative, fire a Telegram alert AND
   keep retrying (don't crash — a flapping feed is still better than a
   dead bot during the capture).

5. **Backpressure.** If the writer queue exceeds 10k items, drop **oldest**
   and log dropped count. Recent ticks matter more than complete history
   for our use case (5-minute trading windows + 60s oracle heartbeat).

6. **`Feed` protocol.** A typed Python `Protocol`:
     `class Feed(Protocol): async def stream(self) -> AsyncIterator[Record]`
   Each concrete feed implements it. Tests inject `FakeWSClient` that
   yields recorded payloads at recorded timing. **No real network in unit
   tests.**

7. **Layer boundary.** All real-network code under `src/polymarket_bot/_live/`.
   The shared `Feed` protocol and the `Record` dataclass live in
   `src/polymarket_bot/feeds/protocols.py` (not under `_live/`) so paper-mode
   code in Phase 4 can import the protocol without dragging in real WS
   clients. `import-linter` enforces this.

8. **Failure surface.** Each feed has a private `_health` dict updated each
   message: `{last_seen_ns, msgs_seen, reconnects}`. A separate
   `health.py` task aggregates these and writes a one-line summary to
   `state/feeds_health.json` every 30s. Operator's monitoring command is
   `cat state/feeds_health.json`.

Commit the design doc. No `src/` or `scripts/` code yet.

  def active_window_ts(now_utc_s: int) -> int:

TASK 2.4 — Resolver helper (hypothetical + actual)

`src/polymarket_bot/resolver.py`:

  def hypothetical_now(window_open_oracle: float, current_oracle: float) -> Literal["UP","DOWN"]:
      """What does this market resolve as if it ended *right now*?"""
      return "UP" if current_oracle >= window_open_oracle else "DOWN"

  def actual_resolution(window_ts: int, oracle_at_window_open: float, oracle_at_window_close: float) -> Literal["UP","DOWN"]:

Per anti-vibe rule #1: design doc before code, even for ops glue. Short doc:

  /Users/hamad/Desktop/PolyMarket-5m/design/litestream.md
    - What gets replicated: state/trades.db (Phase 6 will populate this with

    - Where: chosen S3 bucket from step 1.

    - Recovery: documented `litestream restore` one-liner.

      network partition (litestream queues locally, drains when reconnected);
      disk full on source (paper bot doesn't write much; <1GB/year worst case).
    - NOT a kill-switch: bot keeps running if litestream fails; the kill-switch
      is the Telegram /halt sentinel from 5.5.

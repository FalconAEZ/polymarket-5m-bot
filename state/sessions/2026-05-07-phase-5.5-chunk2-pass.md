2. **`b932361` — fix: BRPOP TimeoutError**
   - Discovered during VPS smoke at 19:23 UTC: redis-py's `socket_timeout=5.0` fired before the BRPOP server-side `timeout=30` returned, raising `redis.exceptions.TimeoutError`. The generic `RedisError` branch caught it, ratcheted the reconnect backoff up to 30 s, and emitted a noisy WARN every cycle.
   - Two-line fix: drop `socket_timeout`, replace with `health_check_interval=30`; explicitly catch `RedisTimeoutError` and return `None` (drain loop calls again on next tick).
   - Anti-vibe rule #2: `tests/_live/alerter/test_redis_queue.py` — 3 cases (TimeoutError → None no backoff; hit → bytes; server-timeout → None).

3. **`6713b97` — fix: httpx INFO logs leaked Telegram bot token to journal**
   - `httpx` logs every request URL at INFO. The Telegram Bot API URL embeds the bot token in the path, so each `getUpdates` poll wrote the bare token to `journalctl -u tg-alerter`.
   - One-line fix: `logging.getLogger("httpx").setLevel(WARNING)` in `scripts/run_alerter.py::_configure_logging`.
   - Past journal lines cannot be redacted; pre-existing prompt-2 reminder already mandates rotating the token via `@BotFather` /revoke after Phase 5 closes.

`make verify` after fix-2 was 307 passed.

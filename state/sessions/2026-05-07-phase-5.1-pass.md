### 3. Decision recorded — Path B (Any IPv4 + key-only + non-default port + fail2ban)

Operator's workstation runs **NordVPN with rotating exit IPs**. Two paths considered for the Lightsail SSH firewall:

- **Path A** — Lock port 2222 to operator's current public IP. **Rejected.** Per-IP whitelist on dynamic egress is operationally broken (locks operator out 2-3x/week as Nord rotates).
- **Path B** — Leave port 2222 open to `Any IPv4 address`. Rely on layered auth: non-default port + key-only + no root + fail2ban (added in 5.5). **Accepted.**

Why this is safe even before fail2ban: brute-forcing key auth is not feasible (Ed25519 / RSA-4096 keys can't be guessed). The actual attack vector against an internet-exposed sshd with key-only auth is a zero-day in OpenSSH; per-IP whitelist doesn't help with that.

### 4. Ubuntu 24.04 socket-activation gotcha (documented for future sessions)

Ubuntu 24.04 ships sshd with **systemd socket activation** (`ssh.socket` listens on port 22 and spawns a per-connection sshd). When socket activation is in effect, **`Port` directives in `sshd_config` are ignored** because sshd inherits its socket from systemd rather than binding ports itself.

Symptom: `sshd -T` correctly showed both `port 22` and `port 2222`, but `ss -tlnp` only showed port 22 — the `Port 2222` directive was a no-op.

Fix:
```bash
sudo systemctl disable --now ssh.socket
sudo systemctl enable --now ssh.service
sudo systemctl mask ssh.socket   # prevent it coming back on reboot
```

Documented in `runbooks/vps-ssh-lockdown.md` so the next operator (or the next AWS-image) doesn't trip on the same thing.

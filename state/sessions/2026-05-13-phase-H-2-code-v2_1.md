## Bugs surfaced + resolved in-session

### Bug A — chainlink ↔ gamma resolution disagreement (operator-reported twice)

**Symptom:** dashboard shows a window as won/lost; polymarket UI disagrees; ~5 min later the dashboard flips.

**Root cause:** H.2.10 dropped the gamma poll timeout to 30s. Most windows fall through to chainlink-local-fallback BEFORE gamma's `events` endpoint flips `closed=true`. Chainlink and gamma disagree on ~12% of windows (Phase 11.A historic baseline ~33%, so improved). The bot's post-hoc gamma retry runs 5 min after the chainlink-fallback settle and writes a `settled_correction` record when they disagree.

**Resolution:** working as designed — eventual-consistency by spec §15/L11. Dashboard reconciles via Phase 15.5 `apply_settled_corrections` overlay. Tunable: drop `POST_HOC_GAMMA_RETRY_INITIAL_DELAY_S` from 300s → 60s to shrink the wrong-display window to ~90s (deferred follow-up).

### Bug B — multi-fire entries "duplicate" in tape (operator-perceived)

**Symptom:** two near-identical rows per multi-fire window in the decision tape — operator interpreted as a rendering bug.

**Root cause:** correct behavior. Multi-fire 2× produced two independent decisions per window with identical side/price/rationale-modulo-fire_n. Both deployed real capital.

**Resolution:** [H.2.8](commit/b1d860e) added the `fire_n=N/M` badge in DecisionsTape.tsx. [H.2.9](commit/076926a) added the per-fire Bet $ column so the deployed capital is operator-visible per row.

### Bug C — operator reported "1778621700 UP won" but dashboard showed lost

**Symptom:** specific window resolution disagreement from polymarket UI vs dashboard.

**Investigation:** for the operator's flagged window 1778621700, BOTH chainlink AND gamma post-hoc retry agreed: resolution = DOWN. Bot lost. Operator likely misread polymarket UI position name as resolution. Not a bug.

For the LATER operator-flagged window 1778625900: chainlink said UP (bot win), gamma said DOWN. Post-hoc retry caught it; dashboard flipped UP→DOWN. Real disagreement → real correction. Working as designed.

### Bug D — feeds_health.json missing → false-alarm "feeds silent" Telegram alerts

**Symptom:** Telegram alerts at 23:53 UTC and 00:11 UTC: "polymarket-5m-bot: feeds silent ≥ 5min: ...".

**Investigation:** `state/feeds_health.json` doesn't exist on VPS. The watchdog that publishes feed-silent alerts reads this file; if missing or stale it alerts. The bot's actual WS feeds are healthy (continuous fires landing every window).

**Resolution:** deferred follow-up. Track-down what writes `feeds_health.json` and why it's currently absent. Not blocking — fires are the ground truth of feed health.

### Bug E — mid-window restart loses one of two multi-fire fires from `_prime_active_window_state`

**Symptom:** window 1778631600 — fire 1/2 didn't settle for 5 min while fire 2/2 settled in 30s.

**Root cause:** `_prime_active_window_state` only re-primes the MOST RECENT unsettled fire from JSONL after a restart. When H.2.11 throttle restarted at 00:21:12 (54s after both fires landed), only the second fire (5547709b, fire_n=2/2) got primed. The first fire (88e19c23, fire_n=1/2) was orphaned.

**Resolution:** SELF-HEALING. Periodic orphan-recovery sweep (5 min after startup) caught it via `polymarket-recovery` source. Both fires settled to UP @ +$3.76 each. Total delay: 5 min between the two settles.

**Follow-up:** `_prime_active_window_state` should re-prime ALL unsettled fires for the current window, not just the most recent. Tiny code fix; defended in depth by orphan-recovery so not urgent.

### Bug F — CH1 strict-equality false alarm (audit-surfaced)

**Symptom:** audit script reported 2 fires with Δ=0 in production — should be 0 per CH1.

**Root cause:** rationale uses `%+.2f` format → Δ=0.001 renders as `+0.00`. My audit script parsed string → 0.0 and flagged. The actual `d_bps == 0.0` strict-equality check in the code DID hold for these fires (Δ was 0.0001 ish). Spec spirit ("reject no-skew fires") may want `abs(d_bps) < 0.01` — tiny code fix.

**Resolution:** false alarm at audit layer; real invariant holds. Logged as a code-clarity follow-up.
